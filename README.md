# ระบบใบสั่งงานแผนกขึ้นรูปยาง (RB Shop Floor)

เว็บแอปหน้าเดียวภาษาไทยที่แทน **ใบสั่งงานแผนกขึ้นรูปยาง** ที่เคยกรอกด้วยมือ —
ตั้งแต่เปิดใบสั่งงานจากแผนที่วางไว้ ไปจนถึงบันทึกผลจริงของทั้ง 5 หน่วยงาน
แล้วพิมพ์ใบสั่งงานกับป้ายชี้บ่งออกมาใช้ที่หน้างาน

ใช้งานจริงที่ **https://mnpchatai.github.io/Production-RB/**
รหัสผ่านเข้าหน้าเว็บเริ่มต้นคือ `rubber2026`

โครงงานทั้งหมดยึดตามชีต `ใบสั่งงานในแผนก` ของไฟล์ Excel
"ระบบวางแผนการสั่งงานแผนก RB V1.7.1" ที่ใช้อยู่เดิม

## สายการผลิต

```
ใบสั่งผลิต ─→ ชั่งเคมี ─→ ตียาง ─→ ฉีดยาง ─→ อบตู้อบ ─→ อบ HCM ─→ เสร็จสิ้น
 (จาก Excel)   CHEM      MIX      INJ       OVEN      HCM
               Step 0    Step 1   Step 2    Step 3    Step 4
```

| หน้า | ทำอะไรได้ |
|---|---|
| ศูนย์ควบคุมการผลิต | KPI รวม งานเลยกำหนด กราฟผลผลิต 14 วันแยกหน่วย งานค้างรายหน่วย และใบสั่งงานที่กำลังเดิน |
| 1. ใบสั่งผลิต | บรรทัดงานที่วางแผนไว้ในไฟล์ Excel — กดเปิดเป็นใบสั่งงานของแผนก |
| 2. เบิก-จ่ายวัตถุดิบ & ชั่งสาร | บันทึกเคมีขั้นที่ 1-3 (จำนวนถุง น้ำหนัก ผลตรวจ) + ปริมาณสีต่อ 1 เส้น |
| 3. ผสมยาง (Mixing) | วันที่ เวลาเริ่ม-เสร็จ เครื่องจักร อุณหภูมิตียาง ชิ้นงานดี (กก./เส้น) ของเสียพร้อมสาเหตุ |
| 4. ฉีดยาง (Injection) | เพิ่มเวลาตั้งเครื่อง นน.แกะหัว ชิ้นงานดี (กก./ถาด) ตรวจสอบขนาด 4 ค่า และผู้ปฏิบัติงาน 4 ตำแหน่ง |
| 5. อบยาง (Oven) | ตู้อบ อุณหภูมิ ระยะเวลา เวลาเข้า-ออกตู้ |
| 6. อบยาง (HCM) | เครื่องยาว HCM ชิ้นงานดี (กก./ท่อน) ตรวจสอบขนาด 5 ค่า |
| 7. พิมพ์ใบสั่งงาน & ป้ายชี้บ่ง | ใบสั่งงานเต็มรูปแบบตามฟอร์มกระดาษเดิม และป้ายชี้บ่ง 3 แบบ |
| ชิ้นงาน สูตรยาง & BOM | ข้อมูลอ้างอิงจาก Excel + ตั้งค่ามาตรฐานฉีด/อบ/HCM ที่ไฟล์ต้นทางเว้นว่างไว้ |
| ตั้งค่าระบบ | การเชื่อมต่อ Supabase ผู้ใช้งาน พนักงาน เครื่องจักร และสาเหตุของเสีย |

หน้าหน่วยผลิตทั้งห้าใช้โค้ดหน้าเดียวกัน (`unitPage()`) ต่างกันแค่ชุดฟิลด์ที่ประกาศไว้ใน
`RUN_SPEC` ซึ่งลอกมาจากตารางของแต่ละหน่วยในใบสั่งงานกระดาษตรง ๆ

## สถาปัตยกรรม

ไฟล์ `index.html` ไฟล์เดียว — vanilla JS ไม่มี framework ไม่มี build step

```
index.html
├── <style>   design system (ธีมมืด accent ส้ม #e8792b / ฟ้า #3fb3c9) + สไตล์เอกสารสำหรับพิมพ์
├── <script src=cdn.jsdelivr.net/npm/chart.js@4.4.4>   กราฟ (มี fallback ถ้าโหลดไม่ได้)
└── <script>
    ├── UNITS / JOB_STATUS / NAV   ค่าคงที่ของโดเมน
    ├── DATA                       ข้อมูลทั้งหมดจาก Supabase (ไม่มี localStorage)
    ├── state + render()           ยัด innerHTML ใหม่ทั้งหน้าทุกครั้งที่ state เปลี่ยน
    ├── VIEWS[route]               ฟังก์ชันคืน HTML ของแต่ละหน้า
    ├── RUN_SPEC + unitPage()      หน้าหน่วยผลิตทั้งห้า
    └── MODALS[type] + withSave()  ฟอร์มบันทึกผลและการเขียนกลับ Supabase
```

### render() และการรักษาโฟกัส

`render()` สร้าง DOM ใหม่ทั้งหมด ช่องกรอกที่เรียก `render()` ตอน `oninput` จะเสียโฟกัสทุกตัวอักษร
แก้ด้วยแอตทริบิวต์ `data-fid="ชื่อเฉพาะ"` — `renderNow()` จะจำ `data-fid` กับตำแหน่งเคอร์เซอร์
ของ element ที่โฟกัสอยู่แล้วคืนให้หลังสร้างใหม่

**ช่องกรอกใหม่ที่ `oninput` เรียก `render()` ต้องมี `data-fid` เสมอ ไม่งั้นพิมพ์ได้ทีละตัว**

### สองโหมดการเก็บข้อมูล

เลือกได้ที่ **ตั้งค่าระบบ → ข้อมูล** — หน้าจอและวิธีใช้งานเหมือนกันทั้งสองโหมด
เพราะทั้งคู่คุยผ่าน `api()` ตัวเดียวกัน ต่างกันแค่ปลายทาง

| โหมด | เก็บที่ไหน | เหมาะกับ |
|---|---|---|
| **ในเครื่อง** (ค่าเริ่มต้น) | IndexedDB ของเบราว์เซอร์เครื่องนั้น | ใช้เครื่องเดียว ไม่อยากตั้ง Supabase |
| **Supabase** | PostgreSQL บน Supabase | หลายเครื่อง หลายหน่วยงาน เห็นข้อมูลชุดเดียวกัน |

**โหมดในเครื่อง** ไม่ต้องต่ออะไรเลย ข้อมูลอ้างอิงนำเข้าจากไฟล์ `rb_data.json` ที่ได้จาก
`etl.py --json` (ไฟล์ถูกอ่านในเบราว์เซอร์ ไม่ได้อัปโหลดไปไหน) ส่วนบันทึกผลการผลิตเก็บลง
IndexedDB ทันทีที่กดบันทึก มีปุ่มสำรอง/กู้คืนเป็นไฟล์ JSON ไว้ให้ — ใช้ย้ายข้อมูลข้ามเครื่องได้ด้วย

ใช้ IndexedDB ไม่ใช่ localStorage เพราะข้อมูลอ้างอิงจากไฟล์ Excel จริงหนักราว 5 MB
ซึ่งเกินโควตา localStorage (~5 MB) ไปแล้ว

**โหมด Supabase** คุยกับ PostgREST ด้วย `fetch` ตรง ๆ ไม่ผ่านไลบรารี และไล่ดึงทีละหน้า
หน้าละ 1000 แถว เพราะ PostgREST ตัดที่ 1000 ส่วนตาราง BOM มีเจ็ดพันกว่าแถว

ทั้งสองโหมดข้อมูลแบ่งสองกลุ่มเหมือนกัน:

| กลุ่ม | ตาราง | สิทธิ์ |
|---|---|---|
| มาจาก Excel | `rb_books` `rb_item_standards` `rb_bom_lines` `rb_work_order_lines` `rb_formulas` `rb_colors` `rb_customers` `rb_products` | อ่านอย่างเดียว — แก้ที่ไฟล์แล้วนำเข้าใหม่ |
| ของแผนก | `rb_jobs` `rb_chem_weighings` `rb_chem_color` `rb_mixing_runs` `rb_injection_runs` `rb_oven_runs` `rb_hcm_runs` `rb_process_standards` `rb_employees` `rb_machines` `rb_defect_reasons` | อ่านและเขียน |

ตารางกลุ่มล่าง **ไม่มี foreign key ชี้ไปกลุ่มบน** โดยตั้งใจ — ตารางกลุ่มบนถูกล้างแล้วนำเข้าใหม่
ทุกครั้งที่แก้ไฟล์ Excel ถ้าผูก FK ไว้ การนำเข้ารอบใหม่จะลากบันทึกผลการผลิตหายไปด้วย
ใบสั่งงานอ้างถึงบรรทัดใน Excel ด้วย `(book_code, wo_src_row)` ซึ่งคงที่ข้ามการนำเข้า

## การติดตั้ง

### แบบไม่ต้องต่อ Supabase (เร็วที่สุด)

```bash
pip install openpyxl
python3 supabase/rb_planning/etl.py --json rb_data.json --out /tmp/rb-csv \
  --book TOY --name "สมุดงาน TOY" --file "3.ระบบวางแผน...TOY (6926).xlsm" \
  --book IND --name "สมุดงานอุตสาหกรรม" --file "3.ระบบวางแผน...(26).xlsm"
```

เปิดเว็บ → **ตั้งค่าระบบ → ข้อมูล** → นำเข้า `rb_data.json` → เพิ่มพนักงานกับเครื่องจักร → ใช้งานได้เลย

อยากลองก่อนมีไฟล์จริงก็กด **สร้างข้อมูลตัวอย่าง** ที่หน้าเดียวกัน

### แบบต่อ Supabase (หลายเครื่องเห็นข้อมูลชุดเดียวกัน)

ทำตาม [`supabase/rb_planning/README.md`](supabase/rb_planning/README.md) โดยรัน SQL ตามลำดับนี้

| ลำดับ | ไฟล์ | ได้อะไร |
|---|---|---|
| 1 | `schema.sql` | ตารางที่รับข้อมูลจาก Excel |
| 2 | `policies.sql` | สิทธิ์อ่านตารางกลุ่มนั้น |
| 3 | `ops_schema.sql` | ตารางบันทึกผลการผลิต + ข้อมูลหลักของแผนก |
| 4 | `ops_policies.sql` | สิทธิ์อ่าน/เขียนตารางบันทึกผล |
| 5 | `etl.py` → `import.sql` | นำข้อมูลจากไฟล์ Excel เข้า |

จากนั้นสร้างผู้ใช้ที่ Supabase → Authentication → Users แล้วมาตั้งค่าที่
**ตั้งค่าระบบ → เชื่อมต่อ Supabase** และสลับโหมดที่ **→ ข้อมูล**

ไม่ว่าโหมดไหน ก่อนใช้จริงให้เพิ่ม **พนักงาน** กับ **เครื่องจักร** ที่หน้าตั้งค่าระบบก่อน
เพราะหน้าบันทึกผลใช้สองอย่างนี้เป็นตัวเลือก

## เรื่องที่ควรรู้จากข้อมูลต้นทาง

- **มาตรฐานของขั้นฉีด/อบ/HCM ว่างทั้งสองเล่ม** — คอลัมน์ N:AA ของชีต `DATA STANDARD`
  มีหัวตารางแต่ไม่มีข้อมูลสักแถว ระบบจึงเปิดให้กรอกเก็บไว้ในตาราง `rb_process_standards` แทน
  (กดปุ่ม "ตั้งค่า" ที่บรรทัดมาตรฐานในหน้าหน่วยผลิต หรือที่หน้าชิ้นงาน)
- **ไฟล์ Excel ไม่มีวันกำหนดของขั้นอบตู้อบ** — มีแค่ 3 หมุด: เริ่มตียาง / เสร็จฉีดยาง / เสร็จ HCM
- **รหัสชิ้นงานบางรหัสไม่มีมาตรฐาน** — ราว 7% ของบรรทัดใบสั่งงาน หน้าจอจะบอกตรง ๆ ว่าไม่พบ

## การนำขึ้นใช้งาน

deploy ด้วย GitHub Pages จากสาขา `main` — push แล้ว Pages build ให้เองภายในไม่กี่นาที
ไม่มี build step ไม่ต้องตั้งค่าอะไรเพิ่ม (Settings → Pages → Deploy from branch → `main` / `/root`)

ไฟล์เดียวแบบ static เอาไปวางบนเว็บเซิร์ฟเวอร์ไหนก็ได้ ขอแค่ชื่อ `index.html` อยู่ที่ root
และเสิร์ฟผ่าน https หรือ localhost (หน้าล็อกอินใช้ `crypto.subtle` ซึ่งเบราว์เซอร์ปิดไว้บน `file://`)

## ข้อจำกัดที่ควรรู้

- **รหัสผ่านหน้าเว็บเป็นการกันคนเดินผ่าน ไม่ใช่ระบบความปลอดภัย** — hash เก็บฝั่งเบราว์เซอร์
  ใครเปิด DevTools ก็ข้ามได้ ตัวที่ป้องกันข้อมูลจริงคือ RLS + การล็อกอิน Supabase
- **อย่าเปิด policy ให้ `anon`** ตราบใดที่หน้าเว็บอยู่บน URL สาธารณะ เพราะคีย์ฝั่งผู้ใช้
  ฝังอยู่ในหน้าเว็บ เท่ากับเปิดรายชื่อลูกค้า สูตรยาง และ BOM ให้คนทั่วไป
- **ยังไม่มีการแยกสิทธิ์รายหน่วย** — ผู้ใช้ที่ล็อกอินแล้วเขียนได้ทุกหน่วย
  โครง policy สำหรับแยกสิทธิ์เขียนไว้เป็นคอมเมนต์ให้แล้วใน `ops_policies.sql`
- **ชื่อผู้ใช้ที่เลือกในหน้าตั้งค่าเก็บแยกตามเครื่อง** ไม่ได้ผูกกับบัญชี Supabase โดยอัตโนมัติ
  เว้นแต่กรอก `auth_email` ให้พนักงานคนนั้นไว้
- **โหมดในเครื่องแยกกันคนละเบราว์เซอร์** — คนละเครื่องหรือคนละเบราว์เซอร์เห็นคนละชุด
  ล้างข้อมูลเบราว์เซอร์แล้วหายถาวร ต้องสำรองไฟล์ JSON ไว้เอง ถ้าต้องใช้หลายคนพร้อมกันให้ใช้โหมด Supabase
- กราฟโหลดจาก CDN — ถ้าเน็ตเข้าไม่ถึง ระบบยังใช้งานได้ครบ เพียงแต่ช่องกราฟจะขึ้นข้อความแทน
