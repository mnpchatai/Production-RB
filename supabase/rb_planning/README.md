# ย้ายระบบวางแผนการสั่งงานแผนก RB (Excel V1.7.1) ขึ้น Supabase

แปลงไฟล์ `.xlsm` ของระบบวางแผนแผนก RB เป็นตารางจริงบน PostgreSQL/Supabase
ทดสอบกับสมุดงานสองเล่มแล้ว — เล่ม TOY และเล่มยางอุตสาหกรรม

```
etl.py  ── อ่าน .xlsm ─→ CSV ─┬─→ import.sql (psql)     ─→ Supabase
                              └─→ load.py    (REST API) ─→ Supabase
```

> **ข้อมูลจริงไม่ได้อยู่ใน repo นี้** — repo เป็น public ส่วนไฟล์ต้นทางมีรายชื่อลูกค้า
> สูตรยาง และ BOM ของโรงงาน โฟลเดอร์ `data/` จึงถูก gitignore ไว้
> ให้รัน `etl.py` กับไฟล์ Excel ของคุณเองเพื่อสร้าง CSV ขึ้นมาใหม่

## ตารางที่ได้

| ชีตต้นทาง | ตาราง | TOY | อุตสาหกรรม |
|---|---|---:|---:|
| `Master_Rubber` | `rb_formulas` — สูตรยาง/มาตรฐานการตียาง | 46 | 51 |
| `DATA STANDARD` A:M | `rb_item_standards` — มาตรฐานชิ้นงาน RB | 422 | 580 |
| `DATA BOM` A:T | `rb_bom_lines` — สินค้า 1 ตัวใช้ชิ้นงาน RB อะไรบ้าง | 6,513 | 931 |
| `Chronicle_Working` A:R (+S:AX เป็น jsonb) | `rb_work_order_lines` — ใบสั่งงานรายบรรทัด | 519 | 195 |
| `System` D:G | `rb_colors` — รหัสสี | 82 | 101 |
| `System` I:J | `rb_customers` — ทะเบียนลูกค้า | 176 | 286 |
| `System` L:M | `rb_products` — รหัสสินค้าสำเร็จรูป | 1,244 | 926 |
| `LogSheet` | `rb_doc_log` — ทะเบียนรับเอกสาร | 20 | 0 |
| — | `rb_books` — สมุดงานต้นทาง + ค่าที่ค้างบนหน้า System | 1 | 1 |

ทุกตารางมี `book_code` เพราะสองเล่มใช้รหัสคนละชุด — เลขใบสั่งผลิตไม่ซ้ำกันเลย
รหัสชิ้นงานซ้ำกันแค่ 12 รหัส ถ้ารวมเป็นชุดเดียวข้อมูลจะทับกัน

### วิวที่เตรียมไว้

| วิว | ใช้ทำอะไร |
|---|---|
| `v_rb_bom_with_standard` | BOM ที่ต่อค่ามาตรฐาน (น้ำหนักต่อเส้น, % เผื่อเสีย) มาให้แล้ว |
| `v_rb_production_orders` | ยุบใบสั่งงานรายบรรทัดเป็น 1 แถวต่อ 1 ใบสั่งผลิต |
| `v_rb_missing_standards` | รหัสที่ถูกใช้จริงแต่ยังไม่มีแถวใน DATA STANDARD |
| `v_rb_item_standards_all` / `v_rb_bom_all` / `v_rb_work_orders_all` | รวมสองเล่มพร้อมชื่อสมุดงาน |

## วิธีทำ

### 1. สร้างตาราง

Supabase → SQL Editor → วางเนื้อไฟล์ `schema.sql` แล้ว Run
(หรือ `psql "$SUPABASE_DB_URL" -v ON_ERROR_STOP=1 -f schema.sql`)

### 2. แปลง Excel เป็น CSV

```bash
pip install openpyxl

python3 etl.py --out data \
  --book TOY --name "สมุดงาน TOY (6926)"        --file "3.ระบบวางแผนการสั่งงานแผนก RB V1.7.1 TOY (6926).xlsm" \
  --book IND --name "สมุดงานยางอุตสาหกรรม (26)" --file "3.ระบบวางแผนการสั่งงานแผนก RB V1.7.1 (26).xlsm"
```

รหัสสมุดงาน (`--book`) ตั้งเองได้ แค่ต้องไม่ซ้ำกัน และใช้ค่าเดิมทุกครั้งที่นำเข้าซ้ำ

### 3. นำข้อมูลขึ้น Supabase — เลือกทางใดทางหนึ่ง

**ก. psql** (เร็วที่สุด — connection string อยู่ที่ Project Settings → Database)

```bash
cd data && psql "$SUPABASE_DB_URL" -v ON_ERROR_STOP=1 -f ../import.sql
```

**ข. REST API** (ไม่ต้องติดตั้ง psql)

```bash
export SUPABASE_URL="https://xxxx.supabase.co"
export SUPABASE_SERVICE_KEY="service_role key"   # anon key ใช้ไม่ได้ จะติด RLS
python3 load.py --data data
```

**ค. หน้า Table Editor** — Import data from CSV ทีละตาราง ตามลำดับในตารางข้างบน
(ต้องขึ้น `rb_books` ก่อนเสมอ เพราะตารางอื่นอ้าง foreign key มาที่นี่)

ทั้งสามทางรันซ้ำได้ — ล้างข้อมูลเดิมของสมุดงานนั้นก่อนใส่ชุดใหม่

## สิ่งที่ ETL จัดการให้ระหว่างทาง

**รหัสชิ้นงานสองรูปแบบ** — ชีต `DATA BOM` เก็บรหัสโดยมีช่องสีคั่นอยู่ด้วย
(`RB-A2003-02--212-14-19`) ส่วน `DATA STANDARD` ไม่มี (`RB-A2003-02-212-14-19`)
join ตรง ๆ จึงไม่ติดสักแถว ตาราง `rb_bom_lines` เลยมีคอลัมน์ `rb_code_std` ที่
generate ขึ้นใหม่จากชิ้นส่วน (แผนก-สูตร-ประเภท-ยาว-รู-วงนอก) ให้ตรงรูปแบบของ
`rb_item_standards` — จับคู่ได้ **96.4%** ในเล่ม TOY และ **84.5%** ในเล่มอุตสาหกรรม

**รหัสซ้ำใน DATA STANDARD** — ชีตต้นทางเป็นรายการต่อท้ายไปเรื่อย ๆ รหัสเดียวกัน
ซ้ำได้ถึง 268 บรรทัด (ต่างกันแค่ชื่อที่พ่วงสีไว้ ตัวเลขมาตรฐานเหมือนกันหมด)
ETL ยุบเหลือรหัสละแถว เลือกค่าที่พบบ่อยที่สุด แล้วบันทึกไว้ในคอลัมน์
`source_rows` (ยุบมาจากกี่บรรทัด) กับ `name_variants` (มีชื่อกี่แบบ)
เช่น 6,204 บรรทัดในเล่ม TOY ยุบเหลือ 422 รหัส

**ค่าที่ไม่ใช่ข้อมูล** — `#REF!` `#N/A` `#VALUE!` `-` `-----` แปลงเป็น NULL ทั้งหมด
เลขใบสั่งผลิตบางแถวติดเครื่องหมาย `'` นำหน้ามาจากการพิมพ์ใน Excel — ตัดออกให้

**ค่ามาตรฐาน ณ วันที่สั่งงาน** — คอลัมน์ S:AX ของ `Chronicle_Working` เป็นค่าที่
VLOOKUP มาแปะไว้ตอนออกใบสั่ง เก็บทั้งก้อนลง `std_snapshot` (jsonb) เพื่อคงค่า
ประวัติไว้ ไม่ต้องเพิ่มอีก 30 คอลัมน์

## ช่องว่างของข้อมูลต้นทาง (ไม่ใช่บั๊กของ ETL)

เช็คได้จาก `select * from v_rb_missing_standards order by uses desc`

| เล่ม | รหัสที่ใช้ใน BOM แต่ไม่มีมาตรฐาน | รหัสที่ใช้ในใบสั่งงานแต่ไม่มีมาตรฐาน |
|---|---:|---:|
| TOY | 34 รหัส (232 บรรทัด) | 15 รหัส (40 บรรทัด) |
| อุตสาหกรรม | 127 รหัส (144 บรรทัด) | 10 รหัส (13 บรรทัด) |

นอกจากนี้ยังมีสูตรยางที่ถูกอ้างถึงแต่ไม่มีใน `Master_Rubber`
(เล่ม TOY 88 รหัส เล่มอุตสาหกรรม 8 รหัส เช่น `A2004`, `A1002`, `A4501`)
และชื่อลูกค้าในใบสั่งงานที่ไม่อยู่ในทะเบียนหน้า System (TOY 2 ราย อุตสาหกรรม 4 ราย)

## สิ่งที่ไม่ได้ดึงมา

- `ใบวางแผนการสั่งงาน`, `ใบสั่งงานในแผนก`, `ใบสั่งงานฟอร์มเปล่า`, `ป้ายชี้บ่ง`, `(O.o)`
  เป็นฟอร์มสำหรับพิมพ์ ค่าทั้งหมดเป็นสูตรที่ดึงจากชีตอื่นอยู่แล้ว
- `DATA STANDARD` คอลัมน์ N:AA (มาตรฐานการฉีด/อบ/HCM/ขนาดยางร้อน) — ว่างทั้งสองเล่ม
- `DATA BOM` คอลัมน์ V:AP (บล็อก SE) และ AR:BN (บล็อกคำนวณ) — V:AP มีข้อมูลไม่ถึง 35 แถว
  ส่วน AR:BN เป็นผลลัพธ์ VLOOKUP ของฟอร์ม
- มาโคร VBA และฟังก์ชัน `rubberline()` — ต้องเขียนใหม่ฝั่งแอปถ้าจะใช้ต่อ

## ขั้นต่อไป

ตอนนี้ข้อมูลอยู่บน Supabase แล้วแต่ยังไม่มีหน้าจอมาใช้ — แอปใน `index.html`
ยังใช้ข้อมูลตัวอย่างของตัวเองอยู่ (คนละ schema กัน) ถ้าจะต่อเข้าด้วยกันต้องเขียน
adapter แปลง `rb_*` เป็นโครงสร้าง `DB.items` / `DB.bom` / `DB.orders` ที่แอปใช้
