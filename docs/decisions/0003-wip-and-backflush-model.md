# 0003 — วัตถุดิบเดินผ่าน WIP ยังไง และ backflush ตอนไหน

- สถานะ: ตกลงใช้
- วันที่: 2026-09-07
- เกี่ยวข้องกับ: เฟส 3, เฟส 4, INVARIANT ข้อ 3

## บริบท

เฟส 4 กำหนดสองข้อที่ดูขัดกัน: "วัตถุดิบไม่พอห้ามบล็อกการบันทึก" กับ
INVARIANT ข้อ 3 ที่ห้ามยอดสต็อกติดลบสำหรับ item ที่ `allow_negative = false`

และต้องตัดสินใจด้วยว่าวัตถุดิบ "หายไปจากคลัง" ตอนไหน และ WIP ถูกล้างเมื่อไร
มิฉะนั้นวัตถุดิบจะค้างอยู่ใน location WIP ตลอดไป

## ทางเลือกที่พิจารณา

**แยกการบันทึกผลออกจากการตัดสต็อก (เลือก)**
บันทึกผลสำเร็จเสมอ การตัดสต็อกเป็นอีกขั้นตอน ของไม่พอ → ไม่เกิดธุรกรรมสต็อก
แต่ลง `backflush_exceptions` ผูกกับ `client_ref` เดิม แล้วเข้าคิวฝ่ายวางแผน
retry ผ่าน `resolve_backflush_exception` ซึ่งใช้ `uuid5(NAMESPACE, "backflush-fix/<id>")`
จึงตัดซ้ำไม่ได้

ผลคือยอดไม่ติดลบ และหน้างานไม่ถูกบล็อก พร้อมกัน
สิ่งที่ยอมแลกคือ "ยอดที่ตัดค้าง" ซึ่งมองเห็นได้ในคิว ไม่ได้หายไปเงียบ ๆ

**ตั้ง `allow_negative = true` ให้วัตถุดิบทุกตัว — ตัดทิ้ง**
แก้ปัญหาได้ในบรรทัดเดียวแต่ทำลาย INVARIANT ข้อ 3 ทั้งข้อ
ยอดติดลบแปลว่าไม่มีใครรู้ว่าของจริงเหลือเท่าไร ซึ่งเป็นสิ่งที่ระบบนี้มีไว้เพื่อตอบ

**บล็อกการบันทึกเมื่อของไม่พอ — ตัดทิ้ง**
ขัดข้อกำหนดเฟส 4 ตรง ๆ และในทางปฏิบัติพนักงานจะเลี่ยงด้วยการไม่บันทึก
ซึ่งแย่กว่าการบันทึกแล้วมี exception

## วัตถุดิบเดินยังไง

```
เบิก (backflush ที่ขั้นตอนแรก)   issue_to_wo      คลัง -> WIP
ผลผลิต (ขั้นตอนสุดท้าย)          wo_output        (สร้างขึ้น) -> คลังสินค้า
ปิดงาน                            consume_from_wip WIP -> ออกจากระบบ
ยกเลิกหลังเบิก                    return_from_wo   WIP -> คลัง
```

**backflush เกิดที่ขั้นตอนแรกเท่านั้น** ตามสัดส่วน `(qty_good + qty_scrap) / qty_planned`
ของเสียกลางทางจึงทำให้ต้องผลิตซ่อม ซึ่งไปเพิ่มจำนวนที่ขั้นตอนแรก
แล้วเบิกวัตถุดิบเพิ่มโดยอัตโนมัติ — ไม่ต้องมีกลไกพิเศษ

**`wo_output` เป็นธุรกรรมขาเข้าอย่างเดียว** เพราะสินค้าถูกสร้างขึ้นจากกระบวนการ
ไม่ได้ย้ายมาจากที่ไหน ถ้าทำเป็นสองขา (WIP -> คลัง) ยอดของสินค้าสำเร็จรูป
ที่ location WIP จะติดลบทันที

**WIP ถูกล้างตอนปิดใบสั่งผลิต** ด้วย `consume_from_wip` เท่ากับยอดที่ยังค้าง
ของใบนั้น (เบิก − คืน) นี่คือจุดที่ WIP กลายเป็นสินค้าสำเร็จรูปกับส่วนที่สูญเสีย
ในทางบัญชี และเป็นเหตุผลที่ใบที่ปิดแล้วไม่ทิ้งของค้างไว้ในระบบ

## ผลที่ตามมา

- ระหว่างที่ใบสั่งผลิตยังไม่ปิด WIP จะมีวัตถุดิบค้างอยู่จริง ซึ่งถูกต้อง
  และดูได้จากวิว `stock_balances` ที่ location ประเภท `wip`
- ต้นทุนของใบสั่งผลิตนับเฉพาะ `issue_to_wo` หัก `return_from_wo`
  ไม่นับ `consume_from_wip` ซ้ำ เพราะเป็นการย้ายมูลค่าไม่ใช่ต้นทุนก้อนใหม่
- ถ้าใบสั่งผลิตถูกยกเลิกหลังเบิก ต้องคืนของให้หมดก่อน — บังคับด้วย
  precondition ใน `state_machine.py` ไม่ใช่ใน service เพื่อกันการเรียกลัด

## เงื่อนไขที่ต้องกลับมาทบทวน

ถ้าโรงงานต้องการเห็น WIP แยกรายใบสั่งผลิตแบบเรียลไทม์ (ไม่ใช่แค่รวมที่ location)
ให้เพิ่ม location ต่อใบ หรือเพิ่มคอลัมน์ `wo_no` เป็นมิติของวิวยอดคงเหลือ
ไม่ใช่เพิ่มตารางสรุปที่เขียนทับได้
